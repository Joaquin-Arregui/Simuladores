# Como el 30, pero lo que sigue a la union es una evaluacion multiinstancia, y
# el token de Recoger no termina nunca: despues de recoger se queda en Junta_P,
# una union paralela cuya otra entrada viene de una rama al 0 % y no llega
# nunca. Desde Junta_P el token podria llegar a Elige_O, que es el origen de la
# otra entrada de Une_O, pero esa entrada tambien esta al 0 %: no la alcanzara
# nunca. Asi que la union dispara en t=1 solo con Tribunal y Evaluar arranca sin
# lote. La validacion lo tiene que ver como el motor: si comprobara el camino
# hasta el origen de la entrada pero no el peso de la entrada misma, la union
# esperaria para siempre a un token atascado, nunca dispararia, el modelo
# pasaria la validacion y el fallo llegaria al ejecutar. Solo un token que no
# termina distingue las dos cosas: uno que termina acaba dejando disparar la
# union en alguna ordenacion, y la validacion encuentra el fallo igualmente.
